## 2. Eye rig

The eyes are still the existing torus arcs (`radius 0.15`, `tube 0.06`, arc `1.22π`) on `Left eye` and `Right eye`. No eyelid mesh was added. A lid would be another draw and another intersection with the black lens. Flattening the arc reads as a closed line at this size, and it reuses the geometry.

Each eye now has its own unlit material and its own catchlight material, created once. `apply()` in `createProceduralRobot` sets, per eye:

- Openness as `scale.y`, through `shownOpenness`.
- Curvature as `scale.x`.
- Lift as `position.y` on top of the rest height `0.08`.
- Tilt as `rotation.z`.
- Gaze offset added to the shared cursor look.
- Glow as the unlit color multiplier. The catchlight fades with openness instead of popping off at `0.72`.

A fully closed eye is `scale.y = 0.045` (`EYE_CLOSED`), which leaves a thin green line. Scale is never `0`, so the mesh does not collapse into a degenerate transform. The blink multiplies the expression openness and does not write the expression back.

`pose.eyes` is optional. If it is missing, both eyes fall back to the legacy `eyeScale` and the old mirrored tilt. The director always supplies the pair.

## 3. Expression design

Cues live in `faceExpression.ts`. The presence names did not change: `ATTENTIVE`, `THINKING`, `RESPONDING`, `SPEAKING`, `HAPPY`, `ERROR`, `IDLE`. `CURIOUS` and `SLEEPING` are eye cues, not presence names, so Qwen and the session cannot emit them.

| Read | How it is chosen | Eyes |
| --- | --- | --- |
| Idle | Awake, no presence, not tracking | Matched arcs, soft glow |
| Curious | `TRACKING` while presence is null or `IDLE`, or the dev preview | One eye taller and tilted, the other softer. Offsets stay small |
| Listening | Presence `ATTENTIVE` | Both eyes open and lifted a little |
| Thinking | Presence `THINKING` | Asymmetric openness and gaze. The narrower eye stays above `0.55`, so it does not read as sleep |
| Responding | Presence `RESPONDING` | A slow openness breath of about `0.03`, no glow strobe |
| Speaking | TTS presence `SPEAKING` | Slightly wider arcs and a small lift bob |
| Happy | Presence `HAPPY` | Wide arcs, outer tilt, glow `1.12` |
| Error | Presence `ERROR` | Uneven tilt and openness, dimmer green, no flash |
| Sleeping | Phase `SLEEPING` or `RETURNING_TO_SLEEP` | Both eyes on the closed line. This wins over preview and presence |

Real sleep and the return to sleep clear a dev preview. A wake uses the awake cue and opens with alertness. Happy, error, and the other presence faces still time out through the existing session. Antenna and arm offsets from `applyPresence` are the previous ones. This phase stopped using `blink` as a stand-in squint, so a blink can still play during happy or thinking.

## 4. Blink

`blinkAmount` is unchanged at rest: one blink about every 3.4 seconds, 60 ms close, 50 ms hold, 70 ms open. `shownOpenness` drives the mesh from that value. At blink `1` the shown openness is `EYE_CLOSED` for any expression, and the expression object is not modified. The next open frame restores that expression, including gaze.

While alertness is `0`, `presentCharacter` forces blink to `1` for every ambient blink sample. The periodic blink cannot reopen a sleeping robot. The dev Blink button asks the director for about 3.6 seconds of a 900 ms period. It does nothing while the cue is sleep.

## 5. Transitions

`stepEyePair` uses `1 - exp(-dt / 160)` and clamps `dt` to 100 ms, the same idea as gaze. A long frame cannot leap the whole way, and the blend does not overshoot. Two step sizes that cover the same duration land within a small epsilon. NaN and infinite inputs are replaced with finite rest values before the blend.

Channels stay separate. Blink is only the close-and-reopen. Expression is openness, curve, lift, tilt, gaze offset, and glow. Sleep alertness still closes the pose. Cursor gaze is added in the mesh on top of the expression offset.

## 6. Performance

One `WebGLRenderer`. No postprocessing, no new geometry per frame, no second canvas. The extra cost is two small unlit materials instead of one shared eye material, and one reused eye-pair buffer in the director. `writeEyeTarget` fills that buffer. The torus segments are unchanged. Pixel-ratio cap, transparent clear, and the 160 DIP circle are unchanged. Window travel is still `setBounds` in the main process.

## 8. Manual check

Quit `npm run dev` and start it again so this build is the one on screen.

1. Wake the robot and leave it idle. The eyes should blink fully shut and reopen, about every few seconds, without changing the arch they return to.
2. Move the cursor. The eyes follow it, and while presence is idle the pair should look slightly curious rather than alarmed.
3. Open chat. In dev, the preview row can show Listening, Curious, Thinking, Responding, Speaking, Happy, Error, Sleeping, Blink, and Idle. Thinking should stay visibly open and uneven. Sleeping should close both eyes. Idle should ease back. Blink should repeat, then stop. These buttons are absent from a production build.
4. Run a demo or Qwen turn: attentive, then thinking, then responding, then a short happy. An error path should look concerned and stay green.
5. Let Pablo speak. The speaking face should be a gentle bob, not a flash.
6. Tray Sleep. The eyes close and stay closed. Wake opens them with the body. Thinking must not reappear unless the chat is actually still in that state.
7. Move, Stop, Return Home, wander, and Neon Trail should behave as in M1.9. Corners of the window still click through. The arms and antenna should look as they did before this phase.

## 9. Known limitations

The closed eye is a flattened arc, not a lid with thickness. At 160 DIP that line is the readable closure. A mesh lid is still an open choice if this reads as a squint on the laptop.

Curious is derived from cursor tracking. It is not a presence name. The dev Sleeping preview closes the eyes only. The body nod still belongs to the real Sleep command.

Responding and speaking are deliberately quiet so they do not strobe. They will not read as strongly as happy or sleep.

`eyeScale` on the presence pose is a single summary (`0.87` thinking, `1.06` speaking, `1.08` happy) for older callers. The mesh uses the eye pair.

Antenna and arm acting is unchanged. M2.0C is the next place for that.
