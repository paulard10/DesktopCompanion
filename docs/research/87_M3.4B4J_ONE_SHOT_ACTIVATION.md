## 7. Main-only one-shot activation design

The existing `createPrivilegedVisionWiringOfflineTest` accepts one additional exact
scope: `one-shot-screen-vision-wiring-test`. It still accepts only registered closed
fake transport/dummy handles and, optionally, the existing disposable test ledger.
Unpackaged trusted-main restrictions and TLS-policy checks are inherited unchanged.

In that scope, `authorizeTestOperation(expectedRequestId)` requires exactly one
argument matching the independently inspected pending main review. Wrong/stale IDs
cannot approve a newer review. Successful approval immediately spends a private
volatile `activationUsed` budget. Cancel, edit, expiry, failure, UNKNOWN, success or
another review never reset it. The handle is frozen, rejects JSON serialization
and cannot be structured-cloned; attachment requires its original WeakMap identity
and one unused session. The request ID is a nonsecret comparison, not a bearer token.

The old TEST scope retains its established zero-argument behavior for existing
independent fake operations. The new budget is **per original activation handle**,
not a claim of process-wide or cross-process global authorization. Trusted main
can construct independent test handles; a future pilot must independently authorize
exactly one native instance and must not automatically construct a replacement.
No preference, localStorage, URL, environment variable or application debug flag
creates this authority. The new CLI flag belongs only to the standalone synthetic
proof; it cannot activate application live inference.
