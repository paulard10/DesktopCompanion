# M1.9C.3 — Wander execution and lease expiry

Status: **passed manual Windows validation.** The later rest and hop tuning is in [M1.9C.4](30_M1.9C.4_WANDER_TUNING.md). Wandering stays off until Enable Wandering. A sleeping robot is not woken.

## 1. No hop

The live log stayed on `wander hold=tracking` after Enable, including while the pointer log said `onTarget=false`. There was no `wander depart`.

`tracking` in the planner means “do not hop.” The overlay was setting that flag from the behavior phase `TRACKING`. That phase means the eyes are following a cursor sample. The main process sends a cursor sample on every visible poll, about every 16 ms, wherever the pointer is. Once the robot is awake, the phase stays `TRACKING` for the whole session. The planner therefore never reached a departure.

The flag is now the body circle only: the same distance test as click-through. Eyes can follow the cursor anywhere. A hop waits only while the pointer is on the body. Leaving the body replans on the next turn. This fix left the 2–5 minute rest and the 45-second quiet gate as they were. M1.9C.4 shortens the rests after that validation.

## 2. No sleep after the lease

The same log ended with `wander explore end`, `wander hold=asleep`, and `tray-sleep`. That is the Sleep command. There was no `wander lease expired`. The hop timer was also the only lease clock, so a tracking rearm could drop the callback that was supposed to end the session.

The lease now has its own timer, armed once for `exploreUntil`. Hop reschedules do not clear it. When it fires, the log is `wander lease expired`, the session closes, and the avatar receives explore `0` (a dropped `null` cannot keep the hold). If the 60-second idle deadline has already elapsed, the next behavior step enters the return to sleep. A wake during the hold no longer moves that deadline once it has elapsed, so a click cannot postpone sleep past the session.

Dev logs, each once per change: `wander lease armed delayMs=…`, `wander hold=… waitMs=… leftMs=…`, `explore deferring sleep`, `explore released sleep`, `wander lease expired`.

## 3. Tests

Fake-clock coverage: a body hover does not depart and does not move the lease; the lease still ends at 6 minutes while the hover flag is set; leaving the body after quiet time can depart inside the lease; a wake after the idle deadline, during the hold, does not revive that deadline; clearing the hold then sleeps. The overlay source no longer treats the gaze phase as the wander block. The main source keeps a separate lease timer and clears it on shutdown.

Manual movement, the neon trail, voice, and click-through were not retuned.

## 4. Manual check

Quit `npm run dev` and start it again.

1. Wake the robot. Enable Wandering. Leave the pointer off the body. Within the 2–5 minute rest, one hop should occur. The log should include `wander depart`.
2. The log should include `wander lease armed` near enable, then `wander lease expired` at about 6 minutes, then `behavior RETURNING_TO_SLEEP` without using the Sleep command.
3. Hovering the body should log `wander hold=tracking` and should not hop until the pointer leaves and the quiet time has passed.
4. Move, Stop, Return Home, Neon Trail, and chat pause should behave as before.
