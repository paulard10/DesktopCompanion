## 1. Packaging audit

Production already loads `app://companion/index.html`, `chat.html`, and `trail.html`. `npm run dev` is the only path that sets `DESKTOP_COMPANION_DEV=1` and uses `http://127.0.0.1:5173/`. `scripts/start.mjs` removes that variable, `ELECTRON_RUN_AS_NODE`, and `DESKTOP_COMPANION_SMOKE` before launching Electron against `dist/`.

Path assumptions that change inside a package:

| Resource | Unpackaged join from `dist/main` | Packaged location |
| --- | --- | --- |
| Overlay preload | `../preload/preload.js` | Inside `resources/app.asar/dist/preload/preload.js` |
| Chat preload | `../preload/chatPreload.js` | Inside the same archive |
| Trail preload | `../preload/trailPreload.js` | Inside the same archive |
| Renderer | `../renderer` | Inside the archive, read by the `app://companion` handler |
| Tray icon | `../../assets/tray.png` | `resources/app.asar.unpacked/assets/tray.png` |
| Whisper | `.local-asr` beside the repo | `process.resourcesPath/speech`, and that directory is absent in this build |
| Preferences, provider, Pablo, Qwen key | `app.getPath('userData')/companion/` | Same folder when the app name stays `desktop-companion` |

`nativeImage` does not reliably read a PNG inside an ASAR archive, so the tray icon is unpacked. The protocol handler uses `node:fs/promises`, which Electron redirects into the archive, so the renderer stays inside `app.asar`.

`app.getName()` follows `package.json` `name` for `npm start`. A top-level `productName` would also rename the `npm start` user-data folder. The builder config sets `productName: desktop-companion` without adding `productName` to `package.json`. The existing folder is `%APPDATA%\desktop-companion`. `%APPDATA%\DesktopCompanion` was not created.

Single-instance locking uses that same app name. A running `npm start` and `DesktopCompanion.exe` share one lock. Quit still closes the preference store, clears wander timers, and destroys the trail window.

C: had enough free space for the Electron runtime download. The unpacked directory is about 369 MiB.

## 2. Tool selection and rationale

electron-builder 26.18.0 is the packager. Current configuration docs are at `https://www.electron.build/docs/configuration` and `https://www.electron.build/docs/win`. It can emit a Windows x64 directory from the existing Electron, TypeScript, and Vite stack. No application framework was added.

The `dir` target writes `release/win-unpacked`. There is no NSIS target, no publisher, and no updater. `publish` is `null`. `npmRebuild` is false because the app has no native addon to rebuild.

The builder warns that `author` is missing. No author was invented. With no certificate configured, signing is skipped. The build is unsigned.

## 6. app:// and preload validation

Production overlay load is `app://companion/index.html`. Chat is `app://companion/chat.html`. The trail page is `app://companion/trail.html`. The Vite URL remains in the compiled main file only on the `options.dev` branch. A packaged process does not set `DESKTOP_COMPANION_DEV`.

Preload paths stay one directory beside the compiled main file: `dist/preload/preload.js`, `chatPreload.js`, and `trailPreload.js`. Inside the archive, `__dirname` is `resources/app.asar/dist/main`, so those relative joins still resolve.

`resolveTrayIcon` keeps the normal `assets/tray.png` join. When that path contains `app.asar` and `app.asar.unpacked/assets/tray.png` exists, it uses the unpacked file. The unpacked tray PNG is 147 bytes.

## 7. User data and safeStorage implications

The packaged identity uses the name `desktop-companion`, so Electron's user-data directory stays `%APPDATA%\desktop-companion`. Settings remain under `companion/`:

- `provider-settings.json`
- `tts-settings.json`
- `qwen-key.bin`
- `user-preferences.json`

No `app.setPath` override was added. No credential file was read, copied, or rewritten while packaging. Windows `safeStorage` uses the current user's DPAPI. The same Windows user reading the same `qwen-key.bin` is the condition that preserves the existing ciphertext. This milestone did not decrypt the key and did not send a Qwen request.

Runtime data stays in AppData. It is not written into `release/win-unpacked`.

## 8. Whisper packaging decision

`.local-asr` contains both the local speech binaries and personal recordings. The whole directory was left out. `extraResources` is empty, so there is no `resources/speech` directory and no `whisper-cli.exe`, DLL set, or `ggml-tiny.bin` in the package.

License and redistribution rights for those files are not established in this repo. Local possession is not packaging permission. In this build, local Whisper is an optional feature whose assets are unavailable. The existing main-process check reports that the assets are unavailable or failed verification. The 1,024 MiB available-memory guard and the microphone consent path are unchanged. Nothing downloads or activates Whisper.

A later speech package, if redistribution is actually allowed, would be a separate allowlist of the pinned binaries and `ggml-tiny.bin`, checked against the SHA-256 pins already in `src/main/localSpeech.ts`, placed only under `resources/speech`. Recordings would stay excluded.

## 13. Smoke results

Smoke was not run. Five `electron.exe` processes from the current `npm start` session were still running (PIDs 1640, 8988, 26536, 33828, 48232). No `DesktopCompanion.exe` was running. Those processes were left alone.

`npm start` and the packaged executable share the single-instance lock. Starting smoke, or the packaged executable, while that session is up exits as a second instance. A second-instance exit is not a smoke pass.

After Tray Quit, and after Task Manager shows neither `electron.exe` nor `DesktopCompanion.exe`, `npm run smoke` can be run from the repo. That smoke still launches the unpackaged `dist/` build. The packaged executable needs the manual checklist below.

## 15. Installer readiness

The directory build is the private test artifact. It is not an installed application. There is no Start Menu shortcut, no uninstaller, no startup registration, and no publish step.

M2.1D.2 can be a private per-user NSIS installer after this unpacked build passes the checklist above. That stage should add a Start Menu shortcut and uninstall support, keep startup-with-Windows off, ship no auto-updater, require no publisher, avoid elevation where a per-user install allows it, state that the build is unsigned, keep the existing `%APPDATA%\desktop-companion` settings on upgrade, and wait for an explicit install approval.

Do not run an installer from this milestone.

## 16. Remaining risks and rollback

Visual behavior of the packaged executable is unconfirmed until the checklist is run. SmartScreen will treat the unsigned executable as an unrecognized app. Whisper stays unavailable until a separate, license-checked, hash-verified `resources/speech` package exists. `safeStorage` decryption of the current Qwen key was not exercised.

The running `npm start` session must be quit before either smoke or the packaged executable is a valid launch. Otherwise the new process exits as the second instance and may surface the already running window.

To drop this packaging experiment without touching M2.1B or M2.1C, delete `release/`, `electron-builder.yml`, `assets/icon.ico`, `scripts/render-app-icon.mjs`, `src/shared/packagedLayout.ts`, and `src/shared/packagedRelease.test.mts`, restore the previous preload and tray paths, and remove the `package:win` script, the `electron-builder` devDependency, and the `release/` gitignore line. Do not `git reset` or `git checkout` the working tree: that would also discard the uncommitted movement controls, preferences, and baseline note. Do not commit or push until that is explicitly requested.
