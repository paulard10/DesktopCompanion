## 4. NSIS compilation

`electron-builder` 26.18.0 ran `makensis` and exited 0. The generated script in `release\0.1.1\builder-debug.yml` includes `build\installer.nsh`. Signing was skipped because no certificate is configured.

The include distinguishes the three cases:

- **First install.** There is no `customInstall` macro, so installation does not write a Run value.
- **Version update.** electron-builder runs the uninstaller already on the machine with `--updated`. `customUnInstall` sees `${isUpdated}` and returns before any registry delete. An approved or disabled entry is left as it is. The uninstaller installed with 0.1.0 does not contain this macro. That older uninstaller is the one an upgrade from 0.1.0 will run. 0.1.0 never created this Run value.
- **Real uninstall.** Without `--updated`, the macro reads only `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\com.desktopcompanion.shell`. It deletes that value and the matching StartupApproved value when the command is this install's `DesktopCompanion.exe`. Other Run names are not read. It does not write HKLM, does not reference user data, and does not delete provider settings, the Qwen credential, or preferences.

`deleteAppDataOnUninstall` is false, so `DELETE_APP_DATA_ON_UNINSTALL` is not defined. `perMachine` is false and `allowElevation` is false, so the active execution level is `RequestExecutionLevel user` and `MULTIUSER_INSTALLMODE_ALLOW_ELEVATION` is not defined. `runAfterFinish: false` defines `HIDE_RUN_AFTER_FINISH`. `createDesktopShortcut: false` defines `DO_NOT_CREATE_DESKTOP_SHORTCUT`. `createStartMenuShortcut: true` leaves the Start Menu shortcut enabled. `packElevateHelper: false` leaves `elevate.exe` out of the package. `publish` is null. There is no updater.

The unit tests mock this behavior. The successful `makensis` run is the compilation evidence.

## 11. Upgrade behavior and limitations

An upgrade uses the same app id, the same uninstall GUID, the same install directory, and the same user-data directory. Running the new installer would replace the installed program files. That was not done.

The upgrade runs the 0.1.0 uninstaller with `--updated`. That older uninstaller has no login cleanup. Because startup is off, there is no Run value for it to keep or remove. After 0.1.1 is installed, a later upgrade will run the 0.1.1 uninstaller and preserve a future startup choice. A real uninstall of 0.1.1 removes only this app's matching per-user value.

The installer was not opened. SmartScreen behavior, the wizard, and the tray checkbox are not yet observed on an installed 0.1.1.

## 12. Manual upgrade checklist

Do this only after a separate approval to upgrade the installed app:

1. Quit DesktopCompanion from the tray if it is open.
2. Confirm the 0.1.1 hash above before launching the installer.
3. Run `release\0.1.1\DesktopCompanion-Setup-0.1.1-x64.exe`.
4. Finish without expecting the app to launch by itself.
5. Confirm Installed Apps shows 0.1.1 and the Start Menu target is the same install directory.
6. Confirm user data is still present and startup is still off.
7. Launch from the Start Menu and repeat the installed functional checks.
8. Open the tray and confirm Start with Windows is unchecked. Enable and disable it only as an explicit test.
9. Confirm Start Awake and Wandering stay independent, and that chat, movement, and Neon Trail are unchanged.

## 13. Rollback

Do not install 0.1.1 if the previous build must stay in place. The recoverable installer is `release\DesktopCompanion-Setup-0.1.0-x64.exe` with the hash in section 7. `release\win-unpacked` is also still the 0.1.0 staging directory.

If 0.1.1 is later installed and should be removed, use Windows Installed Apps. That uninstall is not expected to delete `%APPDATA%\desktop-companion`. Reinstalling from the preserved 0.1.0 installer restores that version. Deleting `release\0.1.1` removes only the new build output.
