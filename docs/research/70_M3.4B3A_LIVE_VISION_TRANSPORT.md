## 7. One-shot authorization and request budget

Review issues a random challenge and immutable visible statement, exact question,
image digest, model, domain and 30-second expiry. A typed, exact statement creates
one opaque WeakMap capability bound to the full request fingerprint and review
generation. Review replacement and Cancel invalidate old permission; wrong,
foreign, reused or expired permits fail before credentials/HTTP.

Run atomically consumes the permit and claims the one-attempt budget before any
asynchronous load or request. There is one **native attempt per module/process**;
all native pilot instances share it. Fake-driver identities have separate shared
offline budgets and never claim the native budget. Failures are terminal for
that attempt, even missing key, transport failure or uncertain completion.
There is no retry, fallback, queue, second request or conversation loop.

This is not an account-wide or cross-process currency limit. Restarting a tool
does not undo provider billing and would require a new human authorization.
The future supervised procedure must launch only one test helper and authorize
exactly one call; no background service or global persistent consent is added.

## 8. Bounded response, timeout and cancellation

One **20,000-ms absolute timer** covers credential load, fetch and body reads.
Abort races each asynchronous phase, including an uncooperative fake promise.
Cancellation/timeout abort the controller; no late credential/response can cause
another HTTP call or a successful stale answer. Signal listeners and timers are
removed. Reader/body cancellation is attempted on all response exits.

Only JSON response MIME, exact final URL and bounded body are accepted. Both
Content-Length and incremental received byte counts enforce **64 KiB**; no
response.text/json unbounded allocation. UTF-8 decoding is strict. The shared
normalizer bounds text to 1600 code units and preserves an explicit truncation
flag. Tools/function calls, refusal, empty answer and malformed JSON fail closed.

Usage is nullable if absent, never invented as zero. Present usage must have
nonnegative safe-integer prompt/completion/total counts, consistent totals,
prompt <=1,000,000 and completion <=160. An over-cap reported completion is an
invalid-usage failure; this cannot retroactively prevent or reverse charges.
Reasoning is not displayed or executed. A returned known-key echo, Data URI or
Bearer-like content is rejected rather than exposed as an answer.

Native cancellation/timeout does **not** guarantee provider cancellation, zero
processing, zero billing or remote erasure. No automatic resubmission follows.
Dropping JavaScript references is not physical-memory zeroing.
