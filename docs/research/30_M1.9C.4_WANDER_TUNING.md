# M1.9C.4 — Balanced wander personality tuning

Status: **implemented for development only.** Ready for manual Windows validation. Wandering stays off until Enable Wandering. A sleeping robot is not woken. Do not push this change.

M1.9C.3 passed on Windows: one autonomous hop, Neon Trail, a six-minute lease, automatic sleep, manual controls, and chat and voice safety. That single hop matched the old 2–5 minute rest. A six-minute session had room for one departure, so the robot felt still.

## 1. Timing

| Gate | Value |
| --- | --- |
| First opportunity | 30–60 seconds (`journeys === 0`) |
| Later rest | 45–90 seconds |
| Quiet time | 45 seconds, unchanged |
| Exploration lease | 6 minutes, unchanged |

The first roll and the quiet gate both have to be finished. Enable starts them together, so the first hop is at 45–60 seconds when nothing else touches the robot. A roll of 30–44 seconds departs only after 45 seconds without direct interaction have already passed. A cursor sample outside the body does not reset that clock. The body circle is still the only pointer block.

A body hover or a body click clears the quiet clock and the hop waits. Chat, listening, speech, and generation drop that chance. The planner does not keep a command to run later. The next check is a new quiet or rest gate.

Return Home is still every third departure, and only when that departure is inside the lease. After the shorter rests, the third departure fits in six minutes.

## 2. Steps

Each wander hop is 80–160 DIP, chosen from the same seed as the direction. The plan carries `hopDip`. `moveBy` passes that distance through the existing nudge path. A manual Move calls `moveBy` with no distance, so it stays 120 DIP. Speed, the 280 ms minimum, the 4000 ms cap, the work-area clamp, and the single-monitor rule are unchanged.

Direction order is a fresh heading first (neither the previous hop nor its reverse), then the previous heading, then the reverse when that is the only way with at least 48 DIP of room.

A new session opened by an intentional wake resets the journey count, so that session also uses the 30–60 second first wait. An open lease is not restarted and is not extended by a hop.

## 4. Tests

Fake clocks cover:

1. With the 45-second quiet gate already satisfied, the first hop is inside 30–60 seconds.
2. Later rests are 45–90 seconds.
3. A body hover or a blocked chat/voice state postpones or skips the hop and does not store it.
4. At least three departures fit in one six-minute lease, and the third is Return Home.
5. A hop leaves `exploreUntil` where it was.
6. Manual yield and Disable/Stop cancel an owned move and do not queue the skipped hop.
7. Sleep behavior tests still pass: wandering off sleeps at 60 seconds, and an open hold still defers idle sleep without extending it.
8. At the lease, and one minute after it, the command and the next schedule are empty.
9. The wander module still has no `setTimeout` or `setInterval`. The main process still uses one hop timeout plus the separate lease timer, and shutdown still clears both.

`npm run typecheck` passed.

`npm run test` passed: 148 tests, 0 failed. That script also builds.

`npm run build` passed. Vite printed the existing chunk-size notice for the renderer bundle.

`npm run smoke` did not pass. The log was `desktop-companion: second-instance-exit` with `started=false`. The development process already holds the single-instance lock. That result is not a smoke pass.

## 5. Manual check

Quit `npm run dev` and start it again so this build is the one on screen.

1. Leave Wandering off, wake the robot, and leave it alone. It should sleep at about 60 seconds, with no hop.
2. Wake it, Enable Wandering, and keep the pointer off the body. The first hop should be about 45–60 seconds later. Later hops should be about 45–90 seconds apart. Several moves, including one Return Home, should fit before six minutes.
3. Hops should be short, about 80–160 DIP, and should change heading. An immediate reversal should be rare.
4. Hovering the body, or opening chat, should skip that chance. The log may show `wander hold=tracking` or `wander hold=blocked`. No extra hop should fire the moment the block ends.
5. At about six minutes the log should show `wander lease expired`, then `behavior RETURNING_TO_SLEEP`, with no further hop.
6. Move, Stop, and Return Home should still win over a wander hop. Neon Trail, click-through, and chat and voice pause should behave as before.
