# M2.0E.4 — Stability and release readiness

Status: **audit only.** No feature code, release setting, dependency, package, or installer was changed. Performance work stays declined. The robot, chat, Whisper, Pablo, Qwen, movement, and Neon Trail stay as validated.

Accepted baseline:

- M1.9 movement and autonomy, M2.0B legacy eyes, M2.0C body motion, M2.0D presence, and M2.0D.1 chat layout are validated.
- [M2.0E.1](42_M2.0E.1_PERFORMANCE_AUDIT.md) found no essential optimization.
- [M2.0E.2A](43_M2.0E.2A_WINDOWS_BASELINE.md) measured sleeping CPU at 1.71% of the machine, awake idle at 3.24%, chat-open idle at 2.16%, and private commit near 243–247 MiB. Five chat cycles did not grow commit.

`docs/research/40_M2.0D_REALTIME_PRESENCE.md` and `docs/research/41_M2.0D.1_CHAT_UX_CLEANUP.md` still say they are waiting for a Windows look. That text is older than the accepted validation. The implementation those notes describe is the one under test here.

## 1. Repository state

Branch `master`. `git rev-parse HEAD` fails because this repository has **no commits**. `git status` shows the whole tree untracked: `src`, `scripts`, `docs`, `assets`, `package.json`, `package-lock.json`, and the rest. Nothing was committed, reverted, or pushed.

## 2. Guided stability procedure

This session did not watch a 45–60 minute pass. The steps below are the user session. Each block starts only when the user has put the app in that state. Mark pass, fail, or skipped, and write one line for anything odd. Demo chat is enough. A real Qwen request is not part of this procedure. The microphone stays off unless block H is reached and the RAM guard allows it.

About 45 minutes without the optional blocks, or about an hour with them.

| Block | Minutes | What to do | Watch for |
| --- | ---: | --- | --- |
| A. Launch and wake | 3 | The robot is visible. Wake it from the tray or a body click. | One window. It wakes once and stays awake. |
| B. Awake idle | 5 | Leave it awake. Do not drag it. Chat closed. Wandering and Neon Trail off. | Ambient motion continues. No freeze, no extra window. |
| C. Sleep and wake | 5 | Sleep from the tray. Wait until the eyes are shut. Wake again. Repeat once. | Sleep wins over any leftover expression. Wake opens the eyes once. |
| D. Chat cycles | 5 | Open and close chat five times. | The same chat window returns. Closing it stops speech. The robot stays up. |
| E. Demo conversation | 5 | Provider stays Demo. Send two short messages. | Replies stream locally. The face follows the turn, then rests. |
| F. Cancel a stream | 3 | Send a demo message and press Stop, or Escape, before it finishes. | The reply stops. Send works again. No second reply appears later. |
| G. Pablo | 5 | Turn speech on. Speak one reply. Press Stop during a second reply. Let a third reply finish. | Speak, Stop, and a natural finish all return to idle. No mic. |
| H. Microphone | 5 | Only if Windows reports at least 1,024 MiB available. Hold the mic, speak, release, and let Whisper fill the draft. Do not send that draft to Qwen. | If available memory is under 1,024 MiB, skip this block. The app should refuse rather than start Whisper. |
| I. Movement | 5 | Chat closed. From the tray, move left, right, up, and down, then Return home. | Each hop stays on the work area. Home returns. |
| J. Chat pauses movement | 4 | Open chat. Try a move. Close chat. Move once more. | The move waits while chat is open and runs after it closes. |
| K. Wandering | 5 | Optional. Enable wandering, leave it, then disable it. | It does not leave immediately, and disable stops it. |
| L. Neon Trail | 3 | Optional. Enable the trail, move once, disable the trail. | Pearls follow the move. Disable removes the trail window. |
| M. Hide and show | 3 | Tray Hide, then Show, then Wake. | Hide leaves no interactive overlay. Show brings the same robot back. |
| N. Quit and start | 5 | Tray Quit. Start `npm run dev` again only after the process is gone. | One instance. It starts asleep, as the behavior tests require. |

Blocks I, K, and L are on the tray only while `npm run dev` is running, or while `DESKTOP_COMPANION_MOVE=1` is set. A normal `npm start` hides them. See the matrix below.

Screen lock and resume are optional and only if the user does them. This audit did not change power settings, and the source has no `powerMonitor` handler for suspend, resume, or lock. Display add, remove, and metric changes do reposition the chat and the overlay.

**User result for A–N:** not collected in this audit.

## 4. Lifecycle and safety

Reviewed in the current source. Nothing here was changed.

| Area | What the code does |
| --- | --- |
| Single instance | `requestSingleInstanceLock`. A second launch logs `second-instance-exit` and exits. The first instance shows the overlay. |
| Shutdown | `before-quit` runs `shutdown` once: wander timers, tray, chat destroy, overlay destroy, trail destroy, then `app.quit`. Overlay close hides the window instead of destroying it. |
| Chat window | `ensureWindow` returns the existing window. Close hides it, disarms the microphone, and sends speech and TTS force-stop. Quit removes the chat IPC listeners and destroys the window. |
| Streams | Stop, reset, and a newer turn abort the in-flight demo or Qwen iterator. Tests cover cancel-before-reply and a happy timer that must not replace a newer turn. |
| Pablo | Stop and dispose return playback to idle. Chat hide sends `ttsForceStop`. |
| Whisper | One job. Cancel kills the child. The temp directory is removed in `finally`. Stderr is drained and not logged. Assets are hash-checked before launch. |
| Sleep and wake | Tray sleep ends a wander session, then sleeps the overlay. The director keeps sleep ahead of presence. Tests cover a single wake, sleep overriding an exploration hold, and presence not opening a sleeping face. |
| Animation loop | The page detaches the loop when the document is hidden or the WebGL context is lost, and attaches it again when the document is shown or the context is restored. |
| Display changes | `display-added`, `display-removed`, and `display-metrics-changed` reposition chat. The overlay has the same screen listeners and removes them on destroy. |
| Suspend and lock | No `powerMonitor` subscription. Not exercised. |
| Unhandled rejections | No `unhandledRejection` or `uncaughtException` handler. `shutdown` is started with `void`. A failure there is not caught. This did not show up in the test run. |

No demonstrated startup crash, duplicate window, or leaked chat listener was observed. The missing rejection handler and the missing suspend path are notes, not a reason to edit working shutdown code.

## 5. Development and production

`npm run dev` (`scripts/dev.mjs`) compiles the main and preload projects, starts Vite, and launches Electron with `DESKTOP_COMPANION_DEV=1`. It removes `ELECTRON_RUN_AS_NODE` and `DESKTOP_COMPANION_SMOKE` from that child. Pages load from `http://127.0.0.1:5173/`.

`npm run start` (`scripts/start.mjs`) requires `dist/main/main.js` and launches Electron with `DESKTOP_COMPANION_DEV`, `ELECTRON_RUN_AS_NODE`, and `DESKTOP_COMPANION_SMOKE` removed. It does not remove `DESKTOP_COMPANION_MOVE` if that variable is already set in the shell. Pages load from `app://companion/`.

`npm run smoke` sets `DESKTOP_COMPANION_SMOKE=1`, clears the dev flag, and requires a new process, the m1.6 preload log, a first frame, a disposable credential check outside user data, and `quitting`. A second-instance exit is a failure.

| Capability | `npm run dev` | `npm start` |
| --- | --- | --- |
| Robot, sleep, wake, eyes, body motion | On | On |
| Chat, demo replies, Stop, Pablo | On | On |
| Microphone and Whisper, behind the RAM guard and an explicit arm | On | On |
| Qwen, only after the user saves a key and selects that provider | On | On |
| Developer Tools, expression previews, rig probes | On (`import.meta.env.DEV`) | Off |
| Eye-preview IPC applied to the robot | On | Ignored (`if (!dev) return`) |
| Tray Move, Wandering, Neon Trail | On, because dev sets `devMovement` | Off, unless `DESKTOP_COMPANION_MOVE=1` is already in the environment |
| Show Trail Marker | On | Off (`devMarker` follows the dev flag only) |
| Recovery capture | In the tray, off by default, not written to disk | Same |
| Renderer network | CSP allows only `127.0.0.1:5173` | CSP `connect-src 'none'` |

Qwen’s HTTP call is made in the main process. The production renderer policy does not have to allow that host. Demo mode does not call the network. This audit did not launch `npm start`, because the dev instance holds the lock.

A packaged build is not configured. There is no Forge or electron-builder script. `app.isPackaged` would look for speech files in `resources/speech`. An unpackaged run looks in `.local-asr`. That directory is present and contains `ggml-tiny.bin`, `bin/whisper-cli.exe`, and the pinned DLLs. A package would also need `assets/tray.png`, the built `dist` renderer, and a user-supplied Qwen key stored later through `safeStorage` at `%AppData%\desktop-companion\companion\qwen-key.bin`. The key is not part of the repo.

## 6. Security

Existing protections are still in the source and are covered by the passing tests.

- Overlay and chat webPreferences: `sandbox`, `contextIsolation`, `webSecurity` on; `nodeIntegration`, worker integration, and subframe integration off.
- CSP is applied to trusted renderer responses. Production policy is `default-src 'none'` with no eval, no inline script, and no connect target. Development adds only the Vite origin.
- `setWindowOpenHandler` denies popups. Navigation and redirects off the trusted origin are prevented. Webviews are refused. Certificate errors are not bypassed.
- Preload surfaces are the channel lists in `src/shared/ipc.ts`. Renderers do not receive `safeStorage` or the key file. Tests assert the chat renderer source does not call `safeStorage`.
- The key log line is `key-save result=` plus the boolean outcome. Whisper stderr is not written to the log.
- The microphone permission handler allows one audio type, only for an armed chat page, for ten seconds. OS status `denied` or `restricted` refuses the arm. Capture starts from the button, not from chat open.
- Demo sends make no request. Qwen runs only for a user send with a saved key and an accepted Singapore Model Studio endpoint.
- The cursor poll carries screen position for click-through. The sample type has no window titles and no key state. Recovery capture, off by default, makes the whole overlay hit-testable. It is not a screen recorder and it is not stored. Wandering and the trail cannot enable themselves, and the wander scheduler does not touch input devices or models.

No secret value is recorded in this note.

## 7. Findings

### Blocking

- **Packaging.** Nothing in `package.json` produces an installer or a portable exe. `npm start` is a local production-flag launch of the unpackaged tree.
- **No git commit.** The tree cannot be named by a revision. A distributable build needs a commit before it can be reproduced.
- **Clean smoke is unproven in this session.** Smoke printed `second-instance-exit` and failed its own checks (`started`, `preload`, `frame-ready`, `credential`, `quitting` all false). The dev server was left running. That result is not a smoke pass, and it is not a product crash.
- **Production launch is unproven in this session.** `npm start` was not booted beside the dev instance.

### Nonblocking

- No process-level handler for unhandled rejections.
- No suspend, resume, or session-lock handler. Display changes are handled.
- Research notes 40 and 41 still say they are waiting for a Windows look.
- The avatar bundle is 562.32 kB. Vite prints the chunk-size warning. The performance audit already accepted that as Three.js in the avatar entry.
- `DESKTOP_COMPANION_MOVE=1` left in the environment would bring the movement tray back under `npm start`. The start script does not set it.

### Intentional development-only limits

- Wandering, Neon Trail, the move menu, the trail marker, and the chat developer previews are off in a normal production launch.
- The production renderer cannot open network connections. Model calls stay in the main process.
- Whisper refuses to start below 1,024 MiB available. At the two readings here (973.1 and 838.4 MiB) it would refuse.

### Optional later

- A Windows packager, only after a commit and a clean smoke on a machine with no other instance.
- A signed installer and a `resources/speech` layout for the pinned Whisper files.
- A suspend/resume look, if a real lock or sleep ever misplaces the window.
- The long user checklist in section 2, including one `npm start` pass.

## 8. Release readiness

These are three different decisions.

**A. Continued development use: yes.** Keep using `npm run dev`. Typecheck passed, 186 tests passed, the build completed, and the measured idle cost stays in the range already accepted. No optimization and no visual retune.

**B. Personal production use: not yet.** The production flags and the dev-only gates are in place, and demo chat, Pablo, and the microphone guard do not depend on the dev flag. This audit never started `npm start`, and the stability checklist has not been filled in. Personal daily use waits on one production launch after the dev server is quit, plus that checklist. Quitting the dev server was not done here.

**C. A distributable Windows app: no.** There is no packager, no commit, and no clean smoke from this session. Do not package or publish.
