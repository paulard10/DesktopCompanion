## 1. Current platform and calculated docking geometry

The approved perspective SVG, white shell, glossy black surface and green ring
are preserved. Home is still **112 × 88 DIP**, development-only, optional and OFF
at startup. Its mathematical silhouette is unchanged. Static busy/rest ring
illumination and brief event feedback are the only added presentation states.

The existing black ellipse is now explicitly named and synchronized from
`HOME.surface = { cx: 56, cy: 46, rx: 42, ry: 13 }`; its painted values do not
change. The outer top ellipse remains centered at (56,48), radii (51,18), with
12-DIP sidewall depth. Target the black surface, not the window center (56,44)
or the outer ellipse center.

`dockingGeometry.ts` computes the nominal sleeping body's lower tangent in the
current perspective camera: viewport **216 × 224**, nominal framing diameter
**108**, FOV **28°**, body radius **1**, mesh rest scale **1.03/0.98/0.99**, Sleep
nod **0.18 rad** and roll **0.08 rad**. The existing mesh scale numbers are merely
extracted into `BODY_REST_SCALE`; no geometry, camera, material or animation is
retuned. Analytic ellipsoid projection gives **165.3554066 DIP** for the body's
nominal bottom relative to the avatar window. A test projects the real sleeping
mesh vertices through the real camera and requires agreement within **0.15 DIP**.

The native target is:

```text
avatar.x = round(platform.x + 56 - 216/2)
avatar.y = round(platform.y + 46 + 3 - projectedBodyBottomDip())
```

This centers the body horizontally and puts its nominal lower edge **3 DIP**
into the black surface center, rather than floating far above it or burying it.
The actual hover, breathing, transient gestures and polygon discretization are
still animated. This is a calibrated nominal pose, not exact per-frame pixel
tracking or a visually certified landing.

`placeDockableHome` reserves joint workArea space for both full native windows.
It moves the station's provisional anchor left/up as needed, instead of clamping
the avatar off its support point. It preserves dimensions/artwork, uses integer
DIP and rejects invalid/too-small areas or unsafe destinations. All target and
departure rectangles must fit the primary workArea; scale factors are validated
but not multiplied into DIP coordinates. Same-primary-display travel only;
cross-monitor requests are rejected, including gap-crossing paths.

## 2. One movement owner and docking lifecycle

The docking session lives in the existing main-process overlay controller. It
stores one trusted geometry snapshot, display identity/key, phase and intent.
There is no additional application-wide animation/behavior reducer. Native
movement remains `requestTravel` → `stepTravel` → the existing
`applyWindowPosition` writer on the existing **32-ms** actuator. Original
160-DIP/s-derived average duration, minimum 280 ms and smoothstep easing are
unchanged. No teleport or second velocity/position loop is introduced.

```text
undocked --explicit platform click--> waking (only if necessary) --> returning
returning --actual arrival--> settling --400 ms verified--> docked + Sleep
docked --platform/body click or Tray Wake--> waking --IDLE/TRACKING ack--> leaving
leaving --actual departure arrival--> undocked
any active phase --override/failure/hide/topology/hold/timeout--> undocked
```

- No docking starts from showing Home, cursor proximity, startup or smoke.
- An accepted explicit click disables Follow and calls existing main arbitration
  to disable Wandering/its lease. This is deliberately **not automatic restoration**:
  after departure both remain OFF until the user explicitly enables a mode again.
- An awake click refreshes the existing intentional Wake/inactivity deadline and
  starts travel. An undocked sleeping click explicitly wakes first and waits for
  the trusted renderer's IDLE/TRACKING phase before travel. Wake uses the existing
  **700-ms** behavior; no forced advance or alternate wake animation.
- During approach/departure the moving avatar is click-through through the same
  trusted input suppression mechanism; the stationary platform stays eligible.
- Repeated clicks during waking/approach/settling/departure are idempotent. Home's
  existing **180-ms** input rate limit still rejects very rapid repeats.
- Native travel must actually end within **1 DIP** of the target, with the exact
  viewport size, unchanged platform snapshot and display key. A requested target
  or mathematical easing completion is not enough. A mocked native window that
  refuses to move never becomes docked and receives no docking Sleep command.
- Arrival stops the movement interval and arms one **400-ms** settle timeout.
  Unexpected native displacement cancels settling. At timeout, recheck position,
  visibility, station/display validity, interaction holds and awake state. Only
  then mark physically docked and send the existing Sleep command. The existing
  **800-ms** face/body Sleep transition remains renderer-owned; `docked` means
  physical association plus requested Sleep, not a fabricated renderer sleep ack.
- One bounded **20-second** timeout applies per Wake wait or travel leg; entering
  the next leg replaces that timeout. Repeated clicks do not renew it. Settle
  replaces it rather than adding another timer. Cancellation invalidates the job
  object and clears the timeout; late phase/completion callbacks cannot revive it.
- Docked rest has no docking timeout/interval, travel or Follow activity. The
  existing visible cursor sampler and existing sleep renderer cadence remain.

Departure waits for Wake acknowledgement, then uses the same fixed-target travel
engine and confirms actual arrival. It never enables Wandering or restores Follow.
The old Return Home command still uses its original coordinate-based parking
behavior, independently of the platform.

## 3. Foreground alignment and input

Home and avatar retain the same ordinary `floating` always-on-top level. Main
uses **`avatar.moveAbove(home.getMediaSourceId())`** after Home presentation,
validated Home clicks and confirmed docking. The native identifier comes only
from the owned BrowserWindow. Obtaining this identifier does **not** enumerate
desktop sources or capture an image. The installed Electron declarations document
`moveAbove` as relative native z-order; it does not require keyboard focus.

Global Hide destroys Home; re-show recreates it and reasserts the relationship.
Stacking is event-based, not reordered at cursor/render cadence. If relative
stacking fails, Home fails closed and cancels its job; confirmed-arrival stacking
failure prevents the docking Sleep command. Tests verify these calls and no
focus/continuous reorders. **Actual Windows occlusion behavior remains a manual
gate**, including repeated Hide/Show and the requirement that platform artwork
never cover the face, body or arms.

Avatar-over-platform mouse priority is preserved. The exposed platform front
near local **(56,75)** lies outside the docked body's trusted hit region in tests
and remains available to request departure. The rear rim/top can be owned by the
robot where shapes overlap; this is deliberate, not generic click forwarding.

An intentional robot body click while physically docked is a second wake/departure
path. It uses the existing narrow click notification, with exact owner/frame/URL,
no payload, visibility, current interactive mode, body hit and fresh nonfuture
sample checks. The normal fully sleeping body click does not open chat. Ordinary
awake body/chat interactions retain their existing behavior and can safely cancel
a departure through the chat hold; use the exposed platform front for the least
ambiguous repeated-click test. Tray Wake is always a fallback.

Transparent station margins and avatar corners retain mathematical click-through.
No rectangular input expansion, arbitrary renderer hit region, forwarding hook
or administrator requirement is added. Sampling still has its existing finite
delay; real first-click delivery and elevated applications are not proven by mocks.

## 4. Priority and recovery policy

Explicit manual controls outrank docking to preserve the approved manual safety
escape. This intentionally adjusts Prompt 85's suggested ordering, which placed
ordinary manual override below active docking.

| Priority / event | Docking result | Existing behavior retained |
| --- | --- | --- |
| Quit, invalid window/station, render fault, unavailable geometry | Cancel; clear owned travel/deadline | Normal app shutdown / Home fail-closed recovery |
| Display/scale/primary/workArea change | Cancel, invalidate snapshot | Existing workArea recovery; fresh explicit request required |
| Stop, manual Move, Return Home | Cancel before the explicit command | Stop cancels movement; manual/parking travel still works |
| Explicit Sleep or Hide | Cancel without docking Sleep | Existing Sleep or Hide wins |
| Chat, microphone/TTS, generation hold | Reject initially or cancel active docking; no queue | Existing interaction has priority; ordinary manual travel holds unchanged |
| Accepted docking / departure | Sole fixed-target travel owner | Follow/Wandering disabled through existing arbitration |
| Explicit Follow ON | Cancel docking, then honor explicit intent | Follow never auto-wakes the sleeping character |
| Explicit Wandering ON | Main cancels docking before existing enable | Existing planner/lease and sleep gates unchanged |
| Recovery capture ON | Cancel and reject new docking | Tray recovery input remains available |
| Home hidden/destroyed while docked | Clear association, preserve Sleep in place | Tray Wake works; no forced teleport or automatic departure |

Hiding/re-showing Home never resumes an old trip. If the station disappears while
already docked, reopening it does not resurrect the association: use Tray Wake
for in-place recovery or explicitly request a new docking session. Rejected
requests have a brief amber ring feedback and a fixed explanatory tooltip;
active/rest statuses use static green light. No indefinite waiting behind holds.

- Existing sandbox, context isolation, no Node integration, web security, local
  app protocol, permissions and restrictive CSP remain in force. Home continues

  Home still has exactly three bridge methods. Its no-argument click reaches the
