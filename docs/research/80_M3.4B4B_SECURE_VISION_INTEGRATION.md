## 4. Main-owned crop and session identity

The existing selection controller remains the sole native capture owner.
After the user's local confirmation it releases full-display NativeImage
references before crop delivery. The same canonical cropped PNG buffer remains
owned by the existing question session until Discard/Close/expiry.

Screen review resolves that current crop, main-generated image ID, session ID,
exact draft/revision and original preview deadline. It never recaptures, accepts
a replacement image object or reads a file. The renderer receives only the
existing preview copy/Blob plus bounded review metadata. No redundant canonical
crop or retained Base64 request is introduced.

## 5. Scope and exact-question binding

The immutable main-issued ScreenVisionReview includes purpose, fresh request ID,
current session/image IDs, exact validated question/revision, fixed provider,
region/model, endpoint-policy identifier, MIME/dimensions/PNG bytes, output/
timeout/response bounds and review/preview expirations. Scenario is also bound
privately to the permit. Question spacing, accents and line breaks remain exact.

The scope contains no raw PNG, Base64, credential, local path, source coordinates
or private configured hostname. Actual endpoint and request fingerprint stay in
trusted main code, not renderer-supplied fields. Main verifies the existing
review-before-confirm sequence and nonce; it never trusts a renderer-created
grant or a claimed result label.

This enforces ownership and sequence within the trusted application frame; it
does not cryptographically prove physical human input against a fully compromised
renderer. Even a malicious frame forging the valid rehearsal sequence can reach
only the closed fake. Later real activation requires a separate reviewed gate.

## 6. Endpoint and fingerprint

The scope wrapper calls the existing **buildVisionRequest**, using its
screen-vision profile. It is not an alternative serializer. SHA-256 covers the
complete immutable scope plus canonical URL/body/body-byte count. Thus it binds
request/image/session IDs, exact question/image, endpoint, model, limits and expiry.
The private current PNG digest is also rechecked on confirmation.

Review constructs and releases a temporary request, retaining only scope,
nonce and fingerprint. Confirmation rebuilds and compares the exact request
before entering the fake dispatch boundary. Mutation/changed bytes fail closed.

**Endpoint limitation:** this offline flow pins the existing fictional
`offline-ux` Singapore-shaped endpoint. It loads no saved account configuration
and never contacts that host. The existing Singapore URL validator is reused.
This is not verification of a real configured workspace. Later activation must
resolve its trusted endpoint, bind that exact URL in a new review/fingerprint
and authorize it separately; an offline placeholder review cannot be reused.

## 7. Expiration and single-use consumption

The selector's original **120-second** deadline is unchanged, including time
spent selecting/capturing. Review remains **at most 30 seconds**, clipped to that
deadline. No silent TTL extension, automatic renewal or extra idle polling.

Confirmation removes the main-held screen permit synchronously before async
execution. A private attempted-wire WeakSet adds a second object-level replay
barrier; the session's consumed nonce is the actual owned-IPC authorization gate.
Duplicate click/replay cannot create another operation. Timeout, HTTP failure,
unknown outcome or cancellation do not restore permission. Only an explicit
fresh review and confirmation can authorize another **fake** attempt.

No token or request fingerprint is persisted. Existing synthetic-pilot claims
are preserved and remain spent; their receipt namespace is never used here.

## 12. Closed mock boundary and response contract

The typed ScreenVisionWireRequest carries scope, the shared BuiltVisionRequest
and fingerprint. **exchangeVisionRequestMock** receives that exact request for
offline verification, releases it immediately, then delegates only a request ID
to the existing closed script. It does not retain or log pixels/Base64. Tests
inspect this boundary synchronously and verify the exact crop/question/body.

Only a WeakMap-registered mock handle is accepted; a native fetch, arbitrary
callback or object claiming a fake mode is rejected. No supplied callback can
delegate the fake to HTTP. This is a scripted HTTP-shaped reply, not an HTTP
server or authenticated provider connection.

The executor uses the existing normalizeVisionReply and a **64 KiB** response
cap with a finite **20-second** budget, clipped to remaining preview life.
Body/metadata checks, actual TLS, Authorization headers, remote usage/account
validation and billing remain responsibilities of the existing/future reviewed
real transport; none are tested with a real service here.

## 13. Cancellation, errors and unknown outcomes

A microtask boundary after confirmation lets cancellation prevent fake invocation
entirely. Main has already consumed that grant; old-token replay is still blocked.
After fake dispatch, Cancel aborts local waiting, keeps the attempt consumed,
drops later results and does not retry. The message explains that a future real
request already transmitted could still be processed or billed.

Empty/malformed/oversized replies, HTTP 400/401/429/500, stale correlation IDs,
timeout and unknown failures cannot become successful answers. Timeout/unknown
after the fake boundary is explicitly UNKNOWN. Known HTTP errors remain failures.
No raw server exceptions or private contents are logged.

Consent expiry after an already-entered attempt does not create another grant
or discard an otherwise timely response. The unchanged preview deadline remains
the outer lifetime: Discard/Close/expiry aborts, releases references and suppresses
late publication. No closed window can be recreated by a response.
