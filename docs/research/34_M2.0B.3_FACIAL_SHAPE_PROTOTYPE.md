# M2.0B.3 — Facial shape prototype

Status: **rejected.** Legacy torus eyes stay. The contour prototype was removed in [M2.0B.4](35_M2.0B.4_LEGACY_BASELINE.md).

## 1. Approaches

Three iterations of scaling and tilting the torus arcs did not produce a cute Happy face. That path is closed.

| Approach | What it is | Decision |
| --- | --- | --- |
| A. Original torus | The production eyes. A thick arc, closed by vertical scale. | Kept as the safe rig. Not tuned further. |
| B. Curves rebuilt or morphed each frame | A new path every change, then a tube or ribbon along it. | Rejected. It can pass through warped in-between shapes, and it allocates geometry to do it. |
| C. Three authored contours | An open arch, a solid smile wedge, and a short closed line. Built once. Crossfaded by opacity. | **The prototype.** The silhouette changes without stretching a mesh. |

C is the smallest rig that can show a different Happy. The shapes sit on the existing black face, just in front of the lens, in the same neon green. They share the camera and the one WebGL context. No second window, no model file, no postprocessing.

## 2. What the prototype draws

The contours are created once, and only while `npm run dev` is running. A production build does not construct them. The default rig is still the torus, so opening the app looks as it does today until you ask for the comparison.

| Face | Shape | Why it should read |
| --- | --- | --- |
| Idle | Even open arch, close to the original chunky eye | Same character, without tube shading from a non-uniform scale |
| Happy | Solid upward crescent, a little wider, not a scaled arch | A filled smile reads at desktop size. It is not a warped torus. |
| Sleeping | Short horizontal line with round ends | The same “clearly shut” idea that already passed, drawn on purpose |

Any other expression, including Listening and Speaking, shows the idle arch on this rig. Those faces are not part of this prototype.

Blink and sleep use the closed line. The smile is never squashed on the way shut. The blink clock is unchanged. Expression changes still ease in about 180 ms, but what eases is opacity, so the in-between cannot become a bent oval. A real sleep, or the Sleeping preview, forces that closed line immediately. Sleep still overrides the preview. Choosing the rig does not clear or replace voice presence. Leaving a face preview returns to the live presence on whichever rig is selected.

The contours glance with the existing gaze. They do not take the expression tilt.

## 4. What you should see

On **Legacy eyes**, Idle, Happy, and Sleeping look as they do now.

On **Shape eyes**:

- Idle is a clean open arch.
- Happy is a solid little smile, wider than idle, not a stretched eye.
- Sleeping is two thin closed lines.

The robot stays in the normal 300×400 window. Transitions stay soft. A blink becomes the closed line and comes back.

## 5. Performance

Six small meshes, three shared geometries, three materials. Created once in development, disposed with the robot. Each frame writes opacity and the existing glance. No per-frame geometry. The production bundle grew from 557.09 kB to 557.96 kB and still prints the existing size notice. One WebGL context.

Risk: the shapes are flat decals on a curved lens. If they clip or shimmer, that is a placement issue, not a reason to scale the torus. The materials use a small polygon offset so they stay in front of the face.

## 7. How to compare

Quit `npm run dev` and start it again. The rig switch is a new preload channel, so a hot reload is not enough.

In the dev chat:

1. **Legacy eyes**, then Idle, Happy, and Sleeping.
2. **Shape eyes**, then the same three.
3. Watch a blink on Shape eyes. It should become the closed line, not a squashed smile.
4. Start a real sleep, or let the robot sleep. The eyes stay closed on either rig, and a face preview does not keep showing Happy.
5. Press **Legacy eyes** to return to the torus.

Move, Stop, Home, wandering, Neon Trail, click-through, chat, and voice should behave as before.

## 8. Rollback

Press **Legacy eyes**. That is the default, including after a restart. A production build never constructs the contours.

To remove the experiment, drop the Shape eyes path and the `faceContours` module. The torus rig does not depend on them.
