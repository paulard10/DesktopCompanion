## 3. Investigation and bounded reproduction

One pre-repair native reproduction ran the normal parallel Node test command
after the existing build, with temporary filesystem instrumentation in the
**ignored compiled receipt module only**. It recorded fixed operation names,
sanitized error codes and synthetic UUID filenames, never raw file contents,
configuration, secrets or private paths. The compiled module was restored
byte-for-byte after awaited runner close; subsequent builds regenerated dist.

Result: **774/774 PASS**, approximately **15.60 s** reported test duration.
Recorded filesystem errors were only the **expected EEXIST** for deliberate
duplicate consumed/run/launch claims. There was no unexpected atomic-write error
to attribute to a competing test, antivirus, indexing, disk pressure or timing.
The historical failure was therefore **not reproduced in that native run**.

A focused attempt in the tool's restricted execution container produced
**1 PASS / 61 FAIL** of 62, including **EPERM on rename** and owned-worker/hook
failures. The same focused suites in the native Windows execution context passed
**62/62**. This distinguishes execution environments; it is **not evidence that
the two earlier native default-run failures had the same cause**. Restricted
errors are retained separately, not omitted from the record.

Hypotheses and evidence:

- **Shared namespace / accumulated artifacts: confirmed design weakness.** Both
  suites resolved the same checkout `.local-vision-diagnostics` directory. The
  collector suite restored network guards but did not remove its disk fixtures.
  The instrumented baseline added **65 synthetic runtime artifacts**, in addition
  to its two new instrumentation files. They are preserved, not cleaned away.
- **Reused IDs / stale markers:** tests generate random UUIDs. Only intentional
  duplicates produced observed EEXIST. No accidental ID collision was established.
- **Cross-test deletion:** the old receipt hook matched only its registered UUIDs;
  no broad deletion of the other suite's records was found. The collector had no
  corresponding disk cleanup.
- **Global mocks / clocks:** filesystem replacement mocking is process-local;
  fake clocks are test/worker scoped. No cross-process mock leak was reproduced.
- **Overlapping processes / receipt reading:** the collector already awaits close
  and validates matching receipt state. No missing-close defect was established.
- **Timeout under load:** no confirmed timeout cause in the two prior errors.
  Existing budgets were not increased and no automatic retries were added.
- **Windows filesystem contention / external reader:** remains a hypothesis for
  the historical persistence failure. The native trace does not identify a holder
  or an unexpected error code. No unsupported OS/antivirus diagnosis is claimed.

The repair below addresses the proven namespace/cleanup defect. It is not
presented as a forensic resolution of the unknown historical error.

## 4. Test-only repair

`scripts/vision-pilot-test-fixture.mjs` creates a unique direct child of resolved
TEMP named **desktop-companion-vision-test-***. It copies an explicit allowlist
of **13 first-party runtime files**: the compiled receipt/transport/adapter/image/
fixture/mock modules, their three pure shared dependencies, and the four offline
collector/launcher/worker/preflight scripts. A minimal private CommonJS manifest
preserves module behavior. No node_modules, vault, provider settings, model,
personal screenshot or application profile is copied.

The original receipt module derives its fixed directory from its module path.
Loading an identical copy in the owned replica therefore gives each suite its
own `.local-vision-diagnostics`, **without introducing a production path override,
environment switch, alternative live store or new authorization API**. The normal
checkout receipt directory remains fixed and untouched by the isolated suites.

Both test modules load their receipt/collector/launcher copies from that replica.
Workers inherit the existing minimal environment and original fake-only driver.
No runtime behavior is replaced with a test-only success implementation. A new
regression compares every copied runtime file byte-for-byte with the current
build/source before accepting the fixture.

Cleanup verifies the resolved owned root is a direct TEMP child with the expected
prefix and no root symlink, then removes only that tree. All concurrently started
test work is awaited with allSettled before assertions/cleanup. Actual launcher
closure is checked; an unconfirmed child causes fixture retention rather than
deletion beneath a potentially running process. Historical checkout evidence and
real consumed permission markers are never part of this cleanup.

**Unchanged:** production atomic write/fsync/rename; receipt schema and state
validation; exclusive launch/run/consumed claims; provider/model/endpoint; preview
consent; live deny gate; test timeouts; npm test membership and default concurrency.
All existing assertions remain; no failing test was skipped, excluded or weakened.

## 5. Five new meaningful regressions

1. Copied runtime is byte-identical, has a separate receipt root and rejects
   module paths outside the fixed allowlist.
2. Two namespaces can use the same **synthetic** test ID without reading one
   another; removing one fixture leaves the other's receipt and claim intact.
3. Two real, independent Node processes compete for one **synthetic** grant in
   one namespace: exactly one consumes it. The other must fail with exclusive
   EEXIST, not an arbitrary error. Both validated receipts have zero dispatches;
   exactly one records consumption; both children close and network counters are zero.
4. Three simultaneous fake-success workers preserve their distinct IDs, validated
   answers/receipts and one fake invocation each; collection and close complete.
5. Two simultaneous launches of one synthetic ID admit exactly one child;
   the other is duplicate-or-reservation BLOCKED, without retry or stale success.

Existing tests still cover consumed authorization reuse after receipt deletion,
missing/corrupt/mismatched receipts, no success inferred from exit zero, failed
atomic replacement, bounded cancellation/termination, redaction, expiry, malformed
responses and no fallback. Native credential tests use only isolated dummy profiles.
