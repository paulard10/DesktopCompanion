## 1. Existing settings audit

Reads and writes already lived in the main process, under `app.getPath('userData')/companion/`. This milestone does not replace those files.

| File | Owner | What it stores | Default when missing or unreadable |
| --- | --- | --- | --- |
| `provider-settings.json` | `createProviderSettings` | Chat provider (`demo` or `qwen`) and the Singapore endpoint. Secrets are stripped. | Demo, no endpoint. |
| `tts-settings.json` | `createTtsSettings` | Pablo enabled, auto-read, conversation mode, and speech rate. | Enabled, auto-read off, conversation off, default rate. |
| `qwen-key.bin` | `createFileVault` plus `safeStorage` | The encrypted Qwen key. The renderer never sees the ciphertext. | No key. |

Chat transcripts stay in memory. Speech recordings stay in a temporary directory and are removed with the job. Recovery capture, window position, wander timers, and the exploration lease were not saved. The robot still begins in `SLEEPING` through `initialBehavior`. Tray Wake and Sleep send the existing `wake` and `sleep` behavior commands. `npm start` still deletes `DESKTOP_COMPANION_DEV`. Quit still clears wander timers and destroys the trail window.

Neon Trail and the startup sleep choice had no store. Wandering was session-only and stays that way.

## 2. New schema

`userData/companion/user-preferences.json`, version 1:

```json
{
  "version": 1,
  "neonTrailEnabled": false,
  "startAwake": false
}
```

Both booleans default to false. Unknown fields are ignored. A non-boolean is treated as false. A missing field is false. Version other than `1`, invalid JSON, or a non-object becomes the full default. The file is not created until the user changes a preference.

Wandering is not a field. Active travel, timers, and leases are not written.

## 3. Storage and ownership

`createUserPreferencesStore` in `src/shared/userPreferences.ts` is called from the main process. The renderer and both preloads do not import it. No IPC channel was added.

A save writes a temporary file in the same directory, flushes it, and then replaces the real file. The previous file is moved aside first and restored if the replacement fails. A failed save keeps the previous in-memory values, so the tray checkbox snaps back. Quit calls `close()`, and later updates do not write. The same value is not written again. Logs name a short error code and do not include the path or the file contents.

## 4. Defaults

| Preference | Default | Where it appears |
| --- | --- | --- |
| `neonTrailEnabled` | false | The existing Neon Trail checkbox. It is not repeated under Preferences. |
| `startAwake` | false | Preferences → Start Awake. |
| Wandering | false every launch | The existing Wandering checkbox. It is not saved. |

Checking Start Awake saves the next launch. It does not wake the current session. The Wake item still does that.

## 5. Startup restore

After Electron is ready:

1. The preferences file is read and validated. A bad file does not stop launch.
2. Chat, the overlay, and the tray are created as before.
3. Wander state is `createWanderState()`, which is off.
4. If `neonTrailEnabled` is true, the existing trail controller is enabled. Particles still appear only while the companion is actually moving.
5. The tray checkboxes read those live values.
6. On the first rendered frame, and only when `startAwake` is true and quit has not started, main calls the existing `overlay.wake()`. The renderer has already subscribed to behavior commands by then. Wake does not enable Wandering, open chat, arm the microphone, or call Qwen.

`npm start` with no preferences file still starts asleep, with Neon Trail off and Wandering off.

## 6. Wandering safety

Every launch starts with wandering disabled. Enabling it during a session does not write the preferences file. Quit drops the timer and the lease. The next launch does not resume the session, even if the user had enabled it moments before quitting.

Sleep still ends the current wander session through `endWanderSession` and does not wake the robot. That session flag is still not stored.

## 8. Failure recovery

| Case | Result |
| --- | --- |
| No file | Defaults. Nothing is written. |
| Valid version 1 | Those booleans are used. Extra fields are dropped on the next save. |
| Missing field or a non-boolean | That field stays false. |
| Invalid JSON, a non-object, or another version | Defaults. The bad file is left in place until a later successful save. |
| Unreadable target | Defaults. Startup continues. |
| Write failure, including a replacement that stops before the file is swapped | Previous memory and the previous file stay. The checkbox follows that previous value. |
| The same value saved again | No write. |
| Quit after `close()` | Further updates do not write. |
| Several toggles in a row | The last successful value is the file. Temporary and backup files are removed. |

Automated tests use `os.tmpdir()` directories and delete them. They do not read or write the real Electron userData directory.

## 9. Security

The new file holds two booleans. It does not hold API keys, recordings, transcripts, model output, cursor positions, screen contents, or hardware identifiers. There is no cloud sync and no new network request.

Preserved: renderer sandbox, context isolation, production CSP (`connect-src 'none'`), overlay preload without `invoke`, Qwen `safeStorage`, the Whisper 1,024 MiB guard, microphone arming, and main-process movement. The renderer cannot read `userData` through this feature. Developer tools, Test window move, Reset Trail, and Show Trail Marker stay behind development mode.

## 13. Remaining limitations

- This note does not claim the checklist above passed.
- Start Awake takes effect on the next launch.
- Wandering cannot be remembered on purpose.
- A corrupt preferences file is not rewritten until the next successful change.
- There is no login-at-startup option and no settings window.
- `npm start` is still an unpackaged launch.
- The 562 kB renderer chunk warning is unchanged.
