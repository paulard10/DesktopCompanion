## Camera, identity and WebGL lifecycle

The existing 28-degree perspective camera, world body radius 1, model hierarchy,
shell proportions, face/eye geometry, arm joints, antenna, materials, lights and
color management are unchanged. No rig scale or pose timing was edited.

Camera distance remains the existing formula, now with viewport height 224 and
nominal body diameter 108: approximately **8.318 world units**, versus 10.027 in
the legacy 400-high viewport. The smaller viewport and coordinated projection
reduce apparent size. Perspective is retained; this is not a sprite conversion
or an orthographic redesign.

Canvas CSS still fills the transparent native window. The backing-store DPR cap
remains 2. The existing visible frame callback now compares the current capped
devicePixelRatio with the renderer ratio and resizes only on a change. This
handles same-DIP-size scale changes without another poll, timer or listener.
The existing hidden-window frame gate and WebGL context lifecycle remain.

One first-frame `gl.getError()` check was added. The existing successful WebGL
render diagnostic is forwarded to main only for smoke verification. Smoke now
requires that marker and rejects unavailable/render-failed/context-lost markers;
`frame-ready` alone cannot establish a successful WebGL render.

## Interaction proxy and security

The main process still owns cursor sampling and `setIgnoreMouseEvents`.
Coordinates remain desktop DIP minus live window origin, without multiplication
by Windows display scale. The renderer cannot upload capture geometry.

Compact input uses a union of:

1. The centered, nominal **54-DIP-radius body circle**, with zero extra circle
   slack and zero exit hold.
2. Two mirrored fixed arm capsules, measured relative to the body center. On
   either side the centerline runs from **(60,0) to (72,42)**, radius **25 DIP**.
   The horizontal coordinate is mirrored for the other arm.
3. The existing independently gated chat badge circle, only in awake phases.

The initial 22-DIP arm radius failed the actual-mesh input test during combined
gesture/click pulse. A bounded local geometry probe measured a maximum sampled
centerline distance of approximately 24.4 DIP. The radius was corrected to 25
and the full vertex assertions retained. This fixed an under-covered edge before
manual delivery; tests were not loosened to ignore arm vertices.

Capsules are static motion envelopes, **not pixel-perfect hit testing**. They
intentionally include some transparent pixels near moving arms. Transparent
corners, empty top/bottom regions and side padding remain outside capture. The
antenna is not a guaranteed input target. The clipping-only artificial extrema
and larger development actuator poses are not a promise of exact arm input in
every pose; normal cue samples and wake/sleep samples have separate input tests.

The existing 16-ms visible sampler, 250-ms stale cutoff, hidden-window passthrough,
whole-window recovery (off by default, session-only), Show/Hide/Quit and lack of
forwarded mouse events are preserved. Arm hover also reaches the existing hover
gate so a hovered arm is not ignored by the wander interaction blocker.
There are no hooks, elevation requirements, new IPC channels, permissions or
renderer input-capture authority. Sandbox, context isolation, CSP, `app://`,
navigation checks and permission restrictions are unchanged.

Actual Windows first-click, passthrough and elevated-window behavior still need
manual confirmation. Polling retains a bounded sampling delay; exact painted-pixel
capture is not claimed.

## Performance interpretation

At DPR 2 the compact canvas is **432 × 448 = 193,536 backing pixels**, versus
600 × 800 = 480,000. The 59.68% reduction is pixel arithmetic, not a measured GPU,
RAM or energy reduction. Geometry, materials and Electron process costs remain.

There is still one moving avatar WebGL renderer and the same optional existing
chat/trail windows. No new production timer, polling loop, service or permanent
window was added. Extra steady work consists of fixed capsule arithmetic in the
existing cursor observation and a DPR comparison in the existing visible frame.
The GL error query occurs once at startup. Vite transformation/vertex sweeps are
test-only and are not shipped in the avatar renderer.

The M2.2A v0.1.0 baseline remains historical: approximately 1.03–1.15% machine CPU
asleep, 3.25–4.03% awake idle, about 244/248–249 MiB private commit, with higher
costs when chat/trail were used. Those were short installed-app samples, not new
compact measurements. No new paired CPU/GPU/RAM or battery benchmark was taken.
Smaller raster area alone does not establish an overall performance improvement.

## Known limitations and rollback

Windows appearance, click-through and trail alignment were confirmed by the user
for the tested setup. This does not establish exact input coverage of every
painted pixel/pose. Enlarged diagnostic arm poses, the antenna,
mixed-DPI transitions, elevated underlying apps and very small work areas remain
limitations or manual gates. Tests sample real geometry but are not exhaustive
continuous-pose certification. No new runtime fault was found in final automated
checks; only the arm-envelope under-coverage found by tests was corrected.
Preset changes require a full rebuild/restart of main and renderer together;
renderer hot reload alone cannot resize the main-process window or input shapes.
No runtime profile switch or profile-acknowledgment IPC was introduced.

   and placement through shared consumers; `armProxyDip: null` restores legacy
