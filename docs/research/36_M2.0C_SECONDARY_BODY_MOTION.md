# M2.0C — Secondary body motion

Status: **validated on Windows, 8/8**, after the gesture correction in [M2.0C.3](39_M2.0C.3_VISIBLE_GESTURES.md). Real-time presence continues in [M2.0D](40_M2.0D_REALTIME_PRESENCE.md).

## 1. Rig hierarchy

There is no separate head bone. The face group is the head pivot. Neutral transforms are recorded once when the robot is built and written back every frame.

```text
Root
  Hover                         position.y = pose.hover + bodyBob
    pivot                       rotation from tilt, yaw, and bodyTilt
      Main body                 sphere, rest scale (1.03, 0.98, 0.99), times breathingScale
      Face display              (0, 0.04, 0.56), rotation.x = headTilt, y and z stay 0
        lens
        Left eye                torus, unchanged
        Right eye               torus, unchanged
        Cheek lights
      Antenna base              rest roll 0.12, plus the existing antenna channel and antennaSway
      Left arm                  rest rotation.x 0.2, rotation.z 0.42
      Right arm                 rest rotation.x 0.2, rotation.z -0.42
```

The body sphere is 2 world units across and is framed to the 160 DIP click circle, so 1 world unit is 80 DIP. Arms and the antenna already extend past that circle. They are not hit targets. New motion does not swing them outward: arm lift only pitches the existing rest pose, and antenna sway stays within 0.06 rad.

Motion that was already there is unchanged:

- Idle hover, 0.04 world over 3.4 s.
- Body tilt, 0.055 and 0.03 rad.
- Antenna sway, 0.12 rad.
- Sleep droop, relaxed arms, and the wake scale.
- Presence offsets for thinking, speaking, happy, and error.
- Travel lean, and the greet / nod / explain demo gestures.

Secondary values are added on top of those. They are not a second copy of the idle bob.

## 3. Pose channels

`secondaryMotion.ts` writes one reused pose. The robot is the only module that copies it onto meshes. It does not set window bounds, screen coordinates, click-through, or travel.

| Channel | Mesh | Limit |
| --- | --- | --- |
| `bodyBob` | hover height | ±0.03 world, about 2.4 DIP |
| `bodyTilt` | pivot roll | ±0.05 rad |
| `headTilt` | face pitch | ±0.1 rad |
| `antennaSway` | antenna roll, added to the 0.12 rest | ±0.06 rad |
| `leftArmLift`, `rightArmLift` | shoulder pitch, raised above the rest pose | ±0.12 rad |
| `breathingScale` | body sphere only, not the face or the eyes | 0 to 0.012 |

A missing pose is the same as all zeros. Every channel is clamped and kept finite. The ease is `1 - exp(-dt / 180)`, and a frame is capped at 120 ms. One-shots are a single sine arch of elapsed time, so a missed frame cannot replay them.

## 4. State and gesture mapping

Sleep and the sleeping preview win. Listening, thinking, responding, and speaking follow the cue the app is already publishing. Happy, error, and the responding nod start when that cue becomes current and do not start again while it stays current. Curious and idle are the low-priority holds.

| State | Body |
| --- | --- |
| Idle | Breath up to 0.008 over 4.2 s. Roll sway of 0.01 rad over 5.2 s. No extra bob. |
| Curious | Face looks up slightly, a small roll, antenna leans 0.04 rad. Held. |
| Listening | Antenna leans 0.055 rad and the face lifts a little. No bob. |
| Thinking | Small downward face pitch and a roll the other way. Breath is quieter. |
| Responding | One nod of the face, 0.09 rad. Then the idle hold. |
| Speaking | Antenna 0.03 rad and a quicker breath. Only while the cue is `SPEAKING`. No bob. |
| Happy | One bounce, 0.028 world, and both arms lift 0.12 rad. Then the idle hold. |
| Error | One uneven lean: roll 0.05 rad, arms 0.08 and 0.03 rad. Then the idle hold. |
| Sleeping | Breath up to 0.0035 over 5.6 s. Arms, antenna, face, and bob stay at rest. |
| Waking | The awake pose fades in with alertness. The dev preview plays a 1.2 s slump that settles to rest and does not call `wake()`. |

`SPEAKING` is still published only while Pablo is actually talking. When speech stops, the cue leaves and the antenna ease returns to the idle hold. Closing chat clears a dev eye preview, stops the compare timer, and publishes the real presence again.

## 5. Durations

| Gesture | Length | Peak |
| --- | --- | --- |
| Responding nod | 640 ms | face pitch 0.09 rad |
| Happy bounce | 780 ms | bob 0.028 world, both arms 0.12 rad |
| Error lean | 860 ms | roll 0.05 rad, arms 0.08 and 0.03 rad |
| Waking preview | 1,200 ms | starts slumped, then rest |

The same cue does not restart a gesture. Sleep clears the gesture and remembers the cue, so waking does not play the cancelled bounce again. A later, different cue replaces it.

## 6. Sleep and wake

A sleeping or returning phase clears the eye preview, the fast blink, and the waking preview before the pose is sampled. The sleep sample returns before any nod, bounce, lean, or preview slump is added. There is no timer left running that could wake the pose later.

Real wake is still the existing behavior phase. Alertness scales the awake secondary pose up from the sleep breath. The Waking button is development-only. It is ignored while the robot is actually asleep, and it never moves the sleep deadline.

## 7. Risks

- Happy already raises the body by 0.018 and cocks the antenna by 0.24 through presence. The new bounce is added only during its 780 ms. The combined hover used in the frame test is 0.088 world and still fits the 300×400 view.
- The face pitch carries the eyes with the head. Their torus shape and expression targets are the same.
- Idle still floats on the original 0.04 hover. The new idle layer is breath and a very small roll, so it should not read as a second bounce. If it does, lower `bodyTilt` in the idle hold before touching the eyes.
- A happy presence that is still current after sleep does not replay its bounce. Clicking Happy again while it is already happy also does not replay it. Idle, then Happy, plays it once.

## 8. Performance

One existing WebGL renderer. No new materials, no new geometry, no second context, no shadows, and no postprocessing. The sample and the ease write into two poses created at startup. Sleep still draws at most every 80 ms. The extra work is a few sines and the exponential ease.

Renderer chunk after this pass: `main-C3CsC5a3.js`, 560.55 kB (gzip 141.67 kB). The existing chunk-size notice is still printed. It is not a build failure.

Profiling on the Surface Laptop Go 3, after a clean restart:

1. Open Task Manager, Processes, and expand the Desktop Companion process so the renderer is visible.
2. Wake the robot from the tray. Leave chat closed for one minute. Note the renderer CPU while it is idle.
3. Sleep from the tray. CPU should fall, because drawing slows to the 80 ms sleep cadence. The breath still updates on those drawn frames.
4. Open chat and leave it idle. Note CPU with the page up and the robot awake.
5. Send a short line and let Pablo finish. Speaking motion should be present only while audio plays, then settle.
6. Enable Wandering from the dev tray. Note CPU during a hop and again during the rest. Local body motion must not move the window. The trail, if enabled, still follows the hop only.
