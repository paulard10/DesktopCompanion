Baseline remains `e9ee0e40b80d3c9ccf3728bf8e990d768804f63d`. The uncommitted follow-up in `docs/research/46_M2.1A_GIT_BASELINE.md` was left as it was.

## 1. Root cause

`npm start` never set `DESKTOP_COMPANION_DEV` or `DESKTOP_COMPANION_MOVE`. One flag, `devMovement`, was true only when one of those was set. That flag did two jobs:

- It hid the tray entries for manual movement, Wandering, and Neon Trail.
- It made `runWander`, `onMove`, `onWander`, and `onTrail` return before they did anything.

The planners, the travel controller, and the Canvas 2D trail were already valid. A normal production launch simply never offered them. `DESKTOP_COMPANION_MOVE=1` was an environment override, not the product path, and it also revealed developer items.

## 3. Tray controls

Native Electron menu items, rebuilt whenever the menu is refreshed:

- **Movement** submenu: Move Up, Move Down, Move Left, Move Right, Return Home, and the existing Stop movement command.
- **Wandering** checkbox. `checked` is `wander.enabled`.
- **Neon Trail** checkbox. `checked` is the main-process mirror of `setEnabled`.

The floating overlay has no new buttons. Show, Hide, Wake, Sleep, Open Chat, Recovery, and Quit are unchanged. Recovery was already a production item and stays one.

Clicking a checkbox calls the existing handler and then rebuilds the menu, so a refused toggle snaps back to the real state. Enabling or disabling twice is safe: `enableWander` keeps an open lease, `disableWander` returns an off state, and `setEnabled` returns when the value is unchanged.

## 4. Safe defaults

Every fresh launch starts from the existing constructors:

- `createWanderState()` has `enabled: false` and no scheduled time.
- The trail window starts with `enabled = false`, and main mirrors that with `trailOn = false`.
- Nothing calls `enableWander` or `setEnabled(true)` during startup.
- A manual move only runs from a tray click. It calls `noteManualMove` and the existing `moveBy` / `moveHome` / `stopMovement`. It does not turn Wandering or Neon Trail on.

These choices are not written to disk. Persistence is M2.1C.

Quit still runs `clearWanderTimer()`, `clearLeaseTimer()`, and `trail.destroy()` before `app.quit()`.

## 5. State ownership

One owner per feature:

- Wandering is `WanderState.enabled`, updated only by `enableWander`, `disableWander`, and `endWanderSession`.
- Neon Trail is the private `enabled` flag inside `createTrailWindow`. Main keeps `trailOn` in step with the only production caller, the tray toggle.
- The menu does not keep a second switch. It reads those values when it is built.

Sleep uses the existing `endWanderSession` path. That ends the current lease and clears the timer, and it leaves `enabled` true. The checkbox therefore stays checked. That matches the planner: Sleep does not turn the feature off, and it does not call `wake`. The next session can start only after the user chooses Wake, through the existing `noteWanderWake` path. While asleep, `planWander` issues no hop.

Disabling Wandering calls `disableWander`, which sets `enabled` false, drops the schedule, and stops an in-progress wander hop through the existing `stop` command.

Disabling Neon Trail sets `trailOn` false and calls `setEnabled(false)`, which destroys the trail window. The two features do not call each other.

## 6. Security and developer tools

Product movement does not read `DESKTOP_COMPANION_DEV` or `DESKTOP_COMPANION_MOVE`. `npm start` still deletes `DESKTOP_COMPANION_DEV`. A leftover `DESKTOP_COMPANION_MOVE=1` no longer unlocks anything.

Still hidden unless `npm run dev` sets `DESKTOP_COMPANION_DEV=1`:

- Test window move, including the chat and tray diagnostic hop.
- Reset Trail.
- Show Trail Marker. `showMarker` also refuses when the trail window was not created with `dev`.
- Expression previews, rig diagnostics, Test body tilt, Dev Compare, and the other chat tools inside `import.meta.env.DEV`.

Unchanged boundaries: renderer sandbox, context isolation, `webSecurity`, production CSP (`connect-src 'none'`), overlay preload without `ipcRenderer.invoke`, trail preload without `invoke` / `setBounds` / `setIgnoreMouseEvents`, and main-process authority for `setBounds`. No IPC channel was added. Movement handlers do not call the network, the microphone, Qwen, Whisper, or Pablo.
