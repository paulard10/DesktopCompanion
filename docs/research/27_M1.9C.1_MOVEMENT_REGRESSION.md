# M1.9C.1 — Movement regression fix

Status: **fixed. Stop for a Windows check.** Wandering is still off until Enable Wandering. No new wander behavior was added.

## 1. settleQueued crash

`let settleQueued` was written after the `return` inside `createOverlayWindow`. A `return` leaves every later `let` uninitialized. `function notifySettled` is still hoisted, so shutdown could call it. The binding was in the temporal dead zone, which throws `ReferenceError: Cannot access 'settleQueued' before initialization`.

The smoke path was `frame-ready` → `quitting` → `overlay.destroy` → `haltTravel` → `notifySettled`. That rejection kept the process from exiting, so smoke timed out.

The flag now sits with the other controller state, before the controller is returned. `destroy` sets `destroyed` before `haltTravel`, ignores a second call, and `notifySettled` does nothing once destruction has started. No broad try/catch was added.

## 2. Manual movement

Wandering off does not own travel and does not call `stopMovement`.

The development log that is open now shows a different hold: after Move, the line repeats `travel phase=paused pause=chat`. The chat window is open, and the M1.9A rule still pauses travel until it closes. That pause was then printed on every 32 ms tick, so the console filled and the robot stayed where it was. Closing chat resumes the same move. The log now prints only when the phase or the pause reason changes.

Startup was also calling the wander planner while wandering was disabled, which printed `wander hold=off`. Those callbacks now return immediately unless wandering is enabled. A manual Move, Stop, or Return home does not yield to the planner while it is off.

## 4. Startup and shutdown

Startup still shows the robot asleep and does not schedule a wander timeout. Shutdown sets the wander gate closed, clears that timeout, then destroys the overlay. A queued settle callback sees destruction and does not start travel. A second destroy returns immediately.

## 5. Ownership

- Manual Move, Stop, and Return home always call the movement controller.
- While wandering is on, a manual command clears the wander timer and replaces the hop. Nothing is queued behind it.
- Sleep, an open chat, the microphone, Whisper, and Pablo still pause or block travel as before.
- The neon trail still follows the same travel samples.
