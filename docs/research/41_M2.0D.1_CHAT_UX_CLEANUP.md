# M2.0D.1 — Chat layout cleanup

Status: **implemented, waiting for a Windows look.** The chat controls do the same work as before. The window is no longer a stack of developer buttons. The Electron window itself was not watched in this session.

## Layout issues found

The 380×520 chat window was a single column, but two things ate the conversation.

The welcome line used `position: absolute` inside the transcript area. That area was also free to shrink to nothing. The two development rows were added after the footer, so they took permanent height. Once the transcript area collapsed, the welcome line painted through it and sat on the composer.

The expression buttons and the rig-diagnostic buttons were separate wrapping rows under the composer. With the microphone, Send, Conversation, and Clear conversation beside them, the bottom of the window read as a debug panel. The message list kept whatever height remained.

## Files changed

- `src/renderer/chat.html` — column structure, composer dock, More menu, hidden Developer Tools section.
- `src/renderer/chat.css` — flex constraints, transcript scroller, compact header and composer, bounded settings and tools.
- `src/renderer/chat.ts` — development buttons mount inside Developer Tools. Scroll anchoring follows the transcript scroller.
- `src/shared/chatLayout.test.mts` — layout and production-visibility checks.
- `package.json` — the new test is part of `npm run test`.

Qwen, Whisper, Pablo, presence, the eyes, secondary motion, movement, wandering, and Neon Trail were not changed.

## New chat layout

The page is one column with `min-height: 0` and `overflow: hidden` on the frame.

1. Compact dark header. The status line stays one line.
2. Connection, closed until opened. Its body scrolls and stops at 140px.
3. Transcript. This region grows. The welcome line and the messages share one scroller, `#thread`.
4. Dock, fixed to the bottom: warnings, recording, speech, the composer, the hint, Conversation, and More.

The composer is a normal flex row: message field, Mic, Stop while a reply is running, and Send. Clear conversation is inside More, outside the send form, so opening that menu does not send a message. Enter still sends. Shift+Enter still adds a line.

The window size stays 380×520 DIP, with a minimum of 320×420. Those sizes are CSS pixels, so 100%, 125%, and 150% Windows scaling keep the same arrangement.

## Developer Tools

`#developer` is in the page and hidden. A production build never reveals it. The production chat bundle does not contain the probe labels or `previewPresence`.

In development, the existing preview, Compare, rig, and window-move buttons are created as before and placed in that one section. The section starts closed. Opening it shows wrapping buttons in a 112px scroller. The composer stays on screen, and the transcript keeps the remaining height. Closing it gives that height back to the transcript. Sleep, a busy reply, recording, and playback still reject a preview, as in M2.0D.

## Before and after

Before, the header, connection summary, composer, hint, Conversation, Clear, and two button rows were all fixed height. The transcript was the leftover, and the welcome line could escape it.

After, only the header, the closed Connection row, and the dock are fixed. At 380×520 that leaves about 345px for the transcript. Opening Connection leaves about 205px. Opening Developer Tools leaves about 200px, and the tools themselves scroll. At 320×420 the closed transcript is about 228px, and an open Connection still leaves a scrolling transcript above the composer. In each of those states the welcome line and the message list stay inside the transcript, and the point inside the composer is the message field.

## Windows manual validation

Close the chat and open it again. If the old button rows are still there, quit `npm run dev` and start it again.

1. With Developer Tools closed, the transcript should fill the space above the composer. The welcome line should sit in that space, not across the message field.
2. Type a message. Enter sends in Demo mode. Shift+Enter adds a line and does not send.
3. Open More and choose Clear conversation. The menu should not send the draft.
4. Open Connection, switch between Demo and Qwen, and close it. The composer stays reachable. The API key field stays a password field.
5. Record a short message, edit the transcript, and send it yourself.
6. Use Speak and Stop speech on a reply. Turn Conversation on for one Demo reply and confirm it reads once.
7. Press Stop while a Demo reply is thinking.
8. Resize the window down and back. The composer stays at the bottom and the messages scroll.
9. Open Developer Tools, press one expression and one rig button, then close the section. The transcript should grow again. A production build should not show this section.
