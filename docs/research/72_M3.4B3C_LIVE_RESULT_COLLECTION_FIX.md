## 2. Replacement collection path

`scripts/vision-pilot-collector.mjs` provides:

  successful because exit code is zero. No missing-output resend exists.

## 3. Precise state semantics

`src/main/visionPilotReceipt.ts` records these monotonic states:

1. **NOT_STARTED** — receipt initialized; no review or request evidence.
2. **PREFLIGHT_PASSED** — fixed request construction/validation and review passed.
3. **AUTHORIZATION_CONSUMED** — the valid, unexpired opaque permit entered
   `run`'s one-attempt boundary. Its durable exclusive claim is made before
   asynchronous key loading or any network call. Review/approval alone does
   not consume it. A later local failure still does not restore this permission.
4. **TRANSPORT_INVOKED** — recorded only **after calling** the network-driver
   function, including a synchronous throw. Script/process startup is not this
   state. It proves a local invocation, not provider receipt or billing.
5. **HTTP_RESPONSE_RECEIVED** — an actual Response/status returned from that
   driver. Simulated tests are explicitly labelled `offline-http-test`.
6. **RESPONSE_PARSED** — existing shared normalization, answer and usage
   validation passed. A 200 status alone, empty answer or malformed JSON cannot
   advance here.
7. **RESULT_RECORDED** — a validated final result was atomically written.

Terminal categories are BLOCKED, FAILED_BEFORE_TRANSPORT,
ATTEMPTED_OUTCOME_UNKNOWN, HTTP_ERROR, SUCCEEDED and CANCELLED_AFTER_ATTEMPT.
SUCCEEDED requires HTTP/parse evidence and a nonempty bounded answer, never exit
code alone. A completed 400/401/429/500 is HTTP_ERROR. Timeout, connection loss,
invalid answer and incomplete post-attempt evidence remain unsuccessful/unknown,
with their specific sanitized category retained.

**Crash gap:** a process can die between calling the driver and committing the
TRANSPORT_INVOKED snapshot. If its latest receipt shows consumed authorization,
the collector reports ATTEMPTED_OUTCOME_UNKNOWN even if the durable invocation
count is still zero. That zero is not interpreted as proof of no request.
A pre-authorization interrupted run, by contrast, has no consumed permit and
is FAILED_BEFORE_TRANSPORT. No inferred successful outcome is written retroactively.

## 4. Receipt schema, durability and privacy

Explicitly ignored directory: **`.local-vision-diagnostics/`** under this source
checkout, outside the application/userData and installed release. No telemetry.
No raw process logs are persisted there.

Each `<UUID>.json` is limited to **16,384 UTF-8 bytes**. Its fixed schema includes:

- Local random test ID and live/offline domain.
- Fixed synthetic pilot ID, expected qwen3.7-plus and symbolic Singapore endpoint
  identifier; no private workspace host. The private request fingerprint is
  represented only as a SHA-256 scope binding.
- Consumed flag, observed transport count (0/1), ordered states and complete flag.
- HTTP status/request ID if safe, input/output/total/reasoning **counts**,
  finish reason and bounded elapsed duration.
- Sanitized error category, terminal outcome and optional synthetic-only
  plain-text answer, maximum **1,600 characters**.

Strict keys, label patterns, enums, state dependencies, numeric ranges, UTF-8,
byte caps and matching test ID are revalidated when reading. Extra keys,
malformed/partial JSON, oversized files, symlinks and mismatched IDs fail closed.
Credentials, headers, image bytes/Base64, raw bodies, environment, chat history,
provider reasoning content, arbitrary Error objects and personal screenshots
are not receipt fields. Obvious sensitive answer echoes are rejected as well;
the transport already rejects its known key and data-URI/Bearer echoes.

Receipt integration is attached only to the existing fixed procedural synthetic
request path. It accepts no screenshot/renderer-provided image or question.
No existing preview capture, crop storage, text provider or consent manager
imports the receipt code. A receipt can never grant permission to run anything.

Writes use an exclusive temporary file in the same directory, complete write,
`fsync`, close, then atomic rename. A failed replacement leaves the prior
snapshot; temporary output is cleaned on ordinary errors. Exclusive `.run`,
`.launch` and `.consumed` markers prevent ID/authorization reuse across processes.
Markers contain no key or reusable permit. Missing receipt never clears a claim.
Actual opaque permits remain private in-memory WeakMap capabilities, bound to
the exact existing URL/body fingerprint and 30-second authorization lifetime.

These are process-interruption safeguards, not signed or tamper-proof audit
records. Another process under the same Windows account could alter local
files. Total power loss, filesystem corruption and hardware flush guarantees
were not tested; Windows directory-fsync/power-loss durability is not claimed.
If receipt persistence fails before dispatch, no request proceeds; after an
attempt, incomplete evidence remains unknown and cannot trigger a retry.
